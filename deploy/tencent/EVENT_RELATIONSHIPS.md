# 全量活动与复刻关系

整理日期：2026-10-23（北京时间）。覆盖现存原版客户端的全部 **166 条活动记录，归为 71 组活动**。

本表用于讨论“同一活动只保留最新一期、归入回忆活动”的方案。这里的“原版”指现存数据中该组最早的非回忆记录；“限时复刻”与“原生回忆版”分别列出，不把加入回忆视为又办了一次限时活动。

原版前十期中文顺序和私服排期见 [活动记录](EVENT_HISTORY.md)；开活动及玩法支持范围见 [活动指南](EVENTS.md)。

## 归组规则与资料边界

1. 从已核验哈希的原版简中 master 读取 `EventData`、`TextLabel`、`QuestStory`。166 条 `EventData`、1595 条 `QuestStory` 与仓库原始 JSON 逐项完全一致；中文名称直接取 `_Name` 对应的 `_Text`，没有自行翻译。
2. 以相同类型、正式中文名建立候选组，再核对共享剧情标题；所有含后续版本的普通活动组都有共享剧情标题。设施组还核对同一设施编号，讨伐组核对活动角色；原表明确写出的跨编号 `_BaseEventId` 全部与结果一致。
3. `_BaseEventId` 和名称索引都不能单独作为完整复刻表。万圣节 `20801 → 20811 → 20821 → 20826`、图书馆 `20806 → 20812 → 20827 → 20831` 的名称索引发生变化，但正式中文名、设施和五章剧情标题均一致。
4. “圣天之陨～前篇～／后篇～”、两次不同故事的火焰纹章联动，以及各个新年故事分别保留；相同系列、BGM或角色不是合并依据。
5. 小型特殊活动单独列出。同名再开放按同一组记录；`31003/31005/31006` 没有剧情表内容，依据相同名称索引及类型归组，不宣称已验证其具体玩法或当年机制。
6. 本表只还原现存表中的不同编号关系。同一编号当年若反复开放、日期被覆盖，单份最终版表无法恢复完整次数；“未找到复刻”不等于断言官方历史上绝未重开。
7. 所有展示时间使用北京时间；JSON 同时保留 UTC。这里列的是原版日期，不是本私服开放日期，不把服务器健康或资料完整当作活动可玩证据。

## 关于“最近一次”

- **最近限时编号**：只在非回忆记录中按原版开始时间比较；没有限时复刻时仍是原版编号。
- **按日期最新版本**：把有日期的原版、限时复刻、回忆版一起比较。六组回忆版日期缺失，整组标记“待核日期”；不将“最新已知日期”冒充完整的版本先后结论。
- 表中回忆版独立列出。以后究竟选择最新限时版还是现有回忆版，仍需结合任务、奖励和入口兼容决定；本表不自动选择或启用活动。
