### 域名与 IP 入口

按用户要求实际调用腾讯云备案 API：目标域名 GovStatus=false、LandedStatus=false，账户 PassedCount=0；对已备案公共对照域名返回 true。Ban=false，不能将结果写成腾讯云已经确认具体封禁或 RST 策略。旧 DescribeIcpDomainInfo 的异常空结果没有当作未备案证据，也没有自行解释未说明的 Status 枚举。

服务器本机的原域名证书链及 TLS 1.2/1.3 校验通过，公网域名握手仍被提前重置。有限包头采集中，受控 ClientHello 后约 98 微秒出现异常快速 RST，早于服务端证书发送；这能定位提前中断，不能确定网络设备。

IP 证书使用 Let's Encrypt shortlived 配置，有效期约 160 小时。当前证书到期为北京时间 11 月 6 日 09:31 左右；Caddy 自动续签已配置，后续真实续签尚未到窗口。保留 TCP 80/443 和证书持久目录。auto_https disable_redirects 时，HTTP 80 没有普通健康页面并不说明被拦截；HTTP-01 验证监听由 Caddy 按需处理。

本云环境出站代理对 IP 返回自身的默认证书，不能把它当作生产证书。未关闭校验或绕过环境代理；改用 GitHub 外部执行机完成正常 IP 验证。相关机制见 [游客认证说明](GUEST_AUTH.md)、[Let's Encrypt 公告](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability) 与 [Caddy TLS 配置](https://caddyserver.com/docs/caddyfile/directives/tls)。

### 本次漏掉的验证

最初迁移校验只测了字母数字，未覆盖上游实际使用的全部编号字符，造成 502。后续回归在旧实现失败、修复版通过，未削弱签名、发行方、用途、时效及旧编号一致性检查。

D2 同时把 NPF 和原生游戏 API 切到 HTTPS；外部客户端和合成 MessagePack 检查通过，没有覆盖游戏原生 TLS 客户端，漏掉了后续兼容。D3 恢复旧游戏入口，避开该握手失败；这不等于已经修复原生 TLS 库或查明某个具体 CA 的兼容原因。

D1–D3 的 AuthDiagnostics.error 只接 NPF 公共错误回调。认证成功后的游戏错误不会弹该诊断窗口；应结合游戏提示、准确时间和服务端日志判断阶段，不能认为“没弹窗就没问题”。用户明确游戏流量绕过 VPN，不再只凭截图的 VPN 图标归因。

原 APK 备份不包含游客密码或已下载资源，不等于游戏数据备份。继续原游客，不卸载、不清数据、不重新注册；如要求全量资源重下或卸载，先停止核对。图标下旧地址文字随原资源表保留，不能凭它判断实际请求入口。
